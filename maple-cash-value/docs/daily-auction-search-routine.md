## 중복 방지 절대 규칙

아래 검증을 하나라도 통과하지 못하면 필터 검색을 누르지 않고 즉시 중단한다.

1. 검색 상태는 하나의 공유 객체로 관리한다. 최소 필드는 `queue`, `cursor`, `usage`, `records`, `skipped`, `nextItem`이다.
2. 함수 내부의 독립 변수나 실행 셀별 지역 변수로 `cursor`를 관리하지 않는다. 실행 직전 `queue[cursor]`와 요청 품목명이 같은지 단언한다.
3. 이전 검색어가 있으면 화면의 `검색어 지우기` 버튼을 눌러 완전히 지운다. 입력값을 바로 교체하지 말고 최소 0.5초 뒤 한 품목명만 입력한다.
4. 자동완성 정확 후보가 바로 없으면 총 5초 이상 기다린다. 그래도 없으면 필터 검색 없이 `no_candidate`로 기록한다.
5. 후보 클릭 후 `'<후보명>' 정확히 일치 태그 해제` 버튼이 정확히 1개인지 확인한다. 선택 태그와 대기열 품목명이 다르면 검색하지 않는다.
6. 필터 검색 직전에도 정확 태그를 한 번 더 확인한다. 검색 후에는 결과 제목, 검색 횟수 증가량 1, 대기열 품목명이 모두 일치해야 한다.
7. `cursor`는 성공 가격 또는 건너뛰기 기록이 저장된 뒤에만 1 증가시킨다. 다음 실행은 반드시 갱신된 공유 객체의 `queue[cursor]`를 다시 읽는다.
8. 배치 종료 시 결과 품목명의 고유 개수와 새로 소비한 필터 검색 횟수를 비교한다. 같은 품목이 두 번 나오면 다음 검색을 시작하지 않는다.
9. 쿠폰 카드는 `개당` 가격을, 의상·장비 카드는 결과 제목 이후 첫 번째 `메소` 가격을 읽는다. 한 형식만 가정하지 않는다.
10. 최대 25회 간격으로 GitHub에 체크포인트를 저장한다. 권장 지점은 20, 40, 60, 80, 100회이며 오류를 발견하면 즉시 추가 저장한다. 재개할 때 화면 카운트와 저장된 `usage`가 다르면 화면 값을 우선하고 원인을 기록한다.

## 우선순위 정렬

각 품목은 다음 순서로 정렬한다.

1. 아직 가격이 없는 판매 가능 품목
2. 현재 계산기에서 순이익 또는 메소/캐시가 높은 품목
3. 마지막 갱신일이 오래된 품목
4. 여러 패키지에 동시에 쓰이는 공용 구성품
5. 판매 종료일이 가까운 현재 캐시샵 상품
6. 회전율 주의 패키지 구성품

후보 없음은 이 자동 큐에서 제거하고 수동 확인 목록에만 둔다. 매물 없음은 정확 후보가 확인된 항목이므로 24시간 뒤 한 번만 재확인한다.

## 표준 검색 절차

1. 메이플 옥션 구매 탭, 캐시 필터, 현재 계정, 화면 검색 횟수를 확인한다.
2. 화면 검색 횟수를 저장된 `usage`와 대조한다.
3. 공유 상태의 `queue[cursor]`를 이번 품목으로 확정한다.
4. 이전 검색어가 있으면 화면의 `검색어 지우기` 버튼을 눌러 완전히 지운다.
5. 최소 0.5초 기다린 뒤 확정한 구성품명 하나만 입력한다. 입력값을 지운 직후 새 이름으로 바로 교체하지 않는다.
6. 자동완성 정확 후보를 확인한다. 후보가 없으면 총 5초 이상 기다린다.
7. 후보가 없으면 필터 검색을 누르지 않고 `no_candidate`로 기록한 뒤 수동 목록으로 이동한다.
8. 후보를 선택하고 정확 일치 태그가 이번 품목과 같은지 확인한다.
9. 이전 필터 검색으로부터 최소 5.25초가 지났는지 확인한다.
10. 필터 검색 직전에 정확 일치 태그를 다시 확인한다.
11. 필터 검색을 한 번만 누른다.
12. 화면 검색 횟수가 정확히 1 증가했는지 확인한다.
13. 결과 제목이 이번 후보명과 같은지 확인한다.
14. 쿠폰은 `개당` 가격, 의상·장비는 결과 제목 이후 첫 번째 메소 가격을 기록한다.
15. 결과가 0건이면 `no_listing`으로 기록한다.
16. 기록 저장 후에만 `cursor`를 1 증가시키고 다음 품목명을 다시 읽는다.
17. 20, 40, 60, 80, 100회를 권장 체크포인트로 삼고, 최대 25회를 넘기지 않게 GitHub에 중간 저장한다.

검색어 두 개를 이어 붙이지 않는다. 후보가 없을 때 비슷한 이름을 추측해 다시 검색하지 않는다. 동일 품목이 연속 두 번 결과에 나타나면 자동 실행을 즉시 중단한다.

## 검색하지 않는 항목

- 캐시샵에서 직접 살 수 없는 뽑기 결과물
- 쁘띠 펫 간식 같은 비판매 품목
- 스페셜 프라이스팩, 패스 등 경매장 판매 불가 상품
- 마일리지 전용 참고 품목
- 패키지의 교환 불가 보너스 구성품
- 자동완성 정확 후보가 없어 수동 확인으로 넘긴 품목

`위습의 원더베리 11개`는 묶음명을 검색하지 않는다. `위습의 원더베리` 단가를 한 번 검색하고 계산기에서 11배로 합산한다.

## 저장 형식

가격 확인 성공은 `prices`에 저장한다.

```json
{
  "itemName": "데이터 기준 이름",
  "query": "경매장 정확 후보명",
  "aliases": ["공백 등이 다를 때만"],
  "listingLowestMeso": 123000000,
  "listingLowestText": "1억 2300만",
  "resultCount": 4,
  "status": "ok",
  "filter": "캐시",
  "searchAccount": 1,
  "searchIndex": 25,
  "collectedAt": "2026-07-12T20:00:00+09:00"
}
```

후보 없음은 `skipped`에 저장하되 필터 검색을 누르지 않는다.

- 캐시 가격과 패키지 구성: `maple-cash-value/data/items.json`
- 작업 지시서: `maple-cash-value/docs/daily-auction-search-routine.md`

검색 결과는 25회마다 main과 작업 브랜치에 중간 저장한다. 한 계정이 끝날 때마다 `lastSearchRun`에 사용 횟수, 유효 가격 수, 중복 소모, 다음 시작 품목, 완료 시각을 기록한다.
